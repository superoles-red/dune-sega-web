# Оригинальная кампания Sega USA: мост интерфейса

Код: `tools/em_web_campaign.h`. Данные и воспроизводимый источник:
`data/campaign/manifest.json`, `tools/extract_campaign_manifest.py`.
ROM SHA-256: `b1bbe73186e0902fa8b2db0f227bf306e3d6a80fe592f927d1aa9d60c0f335ba`.
Исходные ROM и переведённые инструкции не менялись. Мост подаёт намерения в
оригинальные меню и наблюдает исходные переходы; сценарии, карты, AI, производство,
цены, исследования, начальные объекты и условия завершения исполняет исходная игра.

## Данные кампании

| Native ID | Дом | Сценарии |
| --- | --- | --- |
| 0 | Harkonnen | SCENH001.INI … SCENH009.INI |
| 1 | Atreides | SCENA001.INI … SCENA009.INI |
| 2 | Ordos | SCENO001.INI … SCENO009.INI |

По девять миссий на дом, всего 27. Таблица `$088124` содержит 24 обычных пароля
для миссий 2–9; пароля первой миссии нет. `Mission 1` — явно отмеченное название
интерфейса, остальные декоративные названия взяты из исходных паролей. Читы лежат
в отдельном `excludedCheats` и не превращены в уровни.

Территория задаётся одной исходной записью `(дом, миссия)` через `$096050` и
`$025FA8…$025FC2`. В этой Sega-версии нет подставленного графа ветвлений DOS:
кнопка ADVICE возвращает исходные указания, а PROCEED запускает тот же сценарий.
Текстовые указатели `$087F38` идут в порядке **briefing, victory, defeat, hints**.
Manifest содержит 108 буквальных английских текстов, три представления домов,
ROM-адреса, SHA и исходные таблицы названий музыкальных/звуковых тестов.

## API и подключение

`em_web_campaign_observe(&em_cpu)` вызывается перед прочими input-адаптерами и
`machine_step`. При результате 1 нижние input-хуки пропускаются для этой
инструкции; сам `machine_step` всё равно выполняется. После успешной загрузки
используется `em_web_campaign_after_load(&em_cpu)`. Он отменяет незавершённые
намерения и проверки результата. Настоящая карта восстанавливает вооружённое
состояние; загрузка меню/результата сама по себе его не создаёт.

`dune_web_campaign_start(house, mission)` ставит запрос, не перезагружая CPU и не
вызывая функции сохранения. В проверенной точке `$01253E` используется исходное
состояние NewHouse (`$FFC14C = 2`), затем настоящий выбор дома. Для миссий 2–9
исходный валидатор `$021902` получает реальную строку ROM. После него выполняется
обычная цепочка `$0264F8 → $026540 → $01609C`, включая briefing и загрузку сценария.
Первая миссия проходит обычную инициализацию дома, без выдуманного пароля.
Старые экраны закрываются исходными нажатиями и нейтральными опросами. На stage4
автоподача прекращается: новый briefing ждёт игрока. Хост освобождает старые
нажатия/очереди мыши и разрешает исполнение CPU; ручная пауза RAF остановила бы и меню.

В ранних credits оригинал закрывает pad-опрос до конца первого staff scroll.
Только явный новый запрос миссии открывает исходный presentation gate: на `$11844`
младший byte D4 становится `$FF`, после чего исходные `$1184A/$11850` читают
нажатие и `$11886` выполняет обычный выход/cleanup. Без запроса весь CPU и исходное
ожидание сохраняются. Ни PC, ни RAM мира этим исключением не подменяются.

В главном меню сначала выбирается настоящая строка START GAME (`D70E = 160`),
затем подаётся native C. Простая подстановка ASCII A была недостаточна: оригинал
подтверждает текущую подсвеченную строку, которой могла оказаться OPTIONS.

`dune_web_campaign_input(action, value)`:

| action | Значение |
| --- | --- |
| 0 | Один исходный raw pad mask |
| 1 | Нажатие строки options |
| 2 | Исходный Right на значении строки options |
| 3 | Строка main menu 0–2 |
| 4 | Native house ID 0–2 |
| 5 | Первый выбор 0 / второй выбор 1 в подтверждении |

Переход к строке выполняется оригинальными направлениями и ожиданием исходной
анимации. Подтверждение одно, после него — нейтральный опрос. Маска не удерживается
между экранами. Ряд options 5 (ввод пароля) не предлагается; ряды 6/7 доступны
только в игровом меню. Оригинальные обработчики меняют музыку, звук, прокрутку,
тестовые записи, выполняют Resume/Restart/Pick another house. Прямой записи этих
опций в RAM у адаптера нет.

У вертикального `$025CB2` подписи берутся из настоящего аргумента меню:
YES/NO для дома, PROCEED/ADVICE для задания. Горизонтальный `$021AE6` использует
исходные DBF0 112/180, DBFA и native C; его текст — `ARE YOU SURE?` из `$021A32`.
`confirmStyle` и `choiceLabels` различают эти формы. Выход из старого горизонтального
подтверждения при новом запросе использует native No.

`continueMask` равен 128 для боевого Start (`$617A/$6E06`); сюжетные опросы и
перелистывание учебника используют mask 16. В `$418B8` face button продвигает
учебный сценарий, а Start 128 завершает его через Back/route. Исходные обработчики
сюжета принимают и остальные face buttons.
В бою campaign API принимает только Start, без скрытых приказов геймпадом.
Tutorial определяется по `$3067C` и его опросу `$418B8`; управление возвращается
оригинальной последовательностью в main menu.

## Тексты и результаты

`messageText` — весь исходный текст, а не уже показанная часть. Оригинальный
`$01FBBA` разбивает его на предложения/параграфы и добавляет CR для переноса.
`$025B02` очищает старое поле и рисует один текущий RAM-параграф. Мост публикует
`visibleMessageText` только после совпадения исходного растра букв с завершённым
VDP-кадром. Это не браузерный таймер и не предположение о длине префикса.
`messageComplete` опирается на исходный флаг показа всех параграфов и тот же барьер.
Активный сохранённый диалог восстанавливается через настоящий frame `$1F9DA`.
Для сохранения после выхода из текстового движка допустим живой native glyph
fallback: поле начинается 16,16, длинный параграф может занимать 288×40 пикселей.

`statsDisplay.ready` появляется на исходных опросах `$272D2/$272FA` после отрисовки.
`score`, `time`, `rank`, `spice/units/structures {you, enemy}` — строки фактической
таблицы VDP, а не заново рассчитанные результаты. Font bank — `$500 + ASCII`.
Время занимает 240,24,40,8: два левых разряда, неподвижный `:` (`$62F5`) и два
правых. Разделитель проверен по исходному растру; он не потерян из-за другого tile ID.
`statsDisplay.victory/mission/campaignComplete` — оформление настоящего экрана,
снятое с его аргументов. Они **не служат доказательством разблокировки**.

## Единственное основание прогресса

Исходный `$229B8` проверяет завершение, `$22A2C` определяет победу. Только вызов
`$22AF0`, результат 1 в `$22AF4` и переход `$22AFC` создают victory edge; поражение —
`$22BDE`. Дополнительно нужен вооружённый настоящий запуск той же миссии/дома.
`outcomeSeq` увеличивается один раз, а идентичность результата записывается до
исходного увеличения миссии `$22B94`. Счётчик локален текущему экземпляру runtime;
его нельзя использовать как глобальный persistent cutoff после перезагрузки страницы.
Девятая победа ведёт в настоящий ending и credits.

Хост хранит разблокировки отдельно по домам. Новая сцена, пароль, загрузка, открытый
экран результатов и успешный старт уровня победой не считаются. Повторное прохождение
не уменьшает ранее открытый максимум. `activeRunArmed/House/Mission` относятся к
текущему запуску; `outcomeHouse/Mission` — к последнему проверенному событию.

## Проверка и пределы доказательства

- 27 native-запусков: все дома × все миссии, настоящий сценарный loader, active map,
  правильные house/mission/territory, исходные стартовые credits/quota и активные объекты.
- 10 повторных входов из pause, старого password input, main с подсвеченным OPTIONS,
  briefing, victory movie/debrief, results, password display, idle main и credits.
  Во всех случаях новый briefing оставался ручным минимум 400 native-кадров;
  запросы/переходы не создали ложных побед.
- Отдельно ранние credits трёх домов: без запроса исходный gate остаётся закрытым
  400 кадров; новый запрос меняет только D4 low byte, проходит исходный exit и
  оставляет новый briefing ручным 400 кадров, без ложных побед.
- Исходные Start/options/горизонтальный No/music/sound/Resume; один финальный input
  на намерение. Одно Continue со stats оставляет отдельный password display;
  второй экран требует второго нажатия.
- Настоящая quota-победа, контролируемое поражение и девятые победы трёх домов с
  последующими native movies/debrief/results/ending/credits.
- Четыре изменения настоящего видимого параграфа в сохранённых диалогах трёх домов,
  completed-frame RGB fence и неизменность всего CPU при наблюдении/чтении.
- Getter результатов не меняет CPU; готовые result-сохранения не выдают victory edge.
- Две отдельные before-outcome фикстуры: active map, fault0, armed1, outcome none/seq0,
  настоящий PC `$22AB2` до исходных predicates. После снимка оригинальное исполнение
  выдаёт ровно один нужный victory/defeat edge.

Команды: `tools/test_em_web_campaign*.c`, `tools/capture_campaign_scenes.c`,
`tools/capture_campaign_before_outcome.c`; скомпилировать `clang -std=c11 -O1 … -lm`.
Логи и сырьё: `.local/campaign-analysis`, `.local/campaign-fixtures`,
`.local/campaign-scenes`. Сводка — `data/campaign/verification.json`.

Это покрытие инициализации и проверенных переходов, не полное заработанное
прохождение кампании. Outcome-фикстуры специально подготавливают native quota
или вызывают оригинальный Building_Free проигрывающей стороны вне продукта.
Runtime cheat/win API не добавлен. Физические телефоны и вся кампания здесь не тестировались.
Три загруженных ending-снимка до первого native poll используют полный исходный кадр;
при обычном прохождении entry-классификация ending/credits наблюдается непосредственно.

Надёжная маршрутизация экранов, граница готового VDP-кадра и native UI sound
описаны в `docs/native-screen-routing.md`. Старый cached poll сбрасывается при
смене сцены; готовность магазина дополнительно требует scene building.

`presentationReady` отдельно разрешает завершённый исходный кадр без готового
ввода: падение стратегической карты, загрузку поля боя, полёт самолётов, финал и
первый проход титров. Новая cinematic phase сбрасывает старый interactive poll.
`outcomeTerminal` отличает поражение/завершившиеся титры от промежуточной победной
статистики девятой миссии. Этот признак не участвует в выдаче прогресса.

Read-only `dune_web_readonly_textless_frame_rgb()` восстанавливает живые слои
завершённого VDP-кадра под текстом и родными кнопками. Оно не заливает карту
чёрным: проверен и настоящий пятистрочный абзац поражения Ordos M1, включая
266 пикселей букв на пятой строке. Вне областей текста/кнопок RGB сохраняется.
Фикстуру воспроизводит `tools/capture_campaign_text_fixture.c` через исходные
Building_Free, predicate поражения и renderer; это контролируемое испытание.

Opt-in `dune_web_frontend_audio()` удерживает исходный Theme0 только в чистом
frontend. У него уже есть бесконечный музыкальный цикл; новый таймер повтора не
добавлялся. В этом профиле всего 13 звуков, поэтому frontend feedback использует
его собственный confirm12 вместо чужих Options25/40/44. В игре обычный SFX25 и
весь звук кампании остаются исходными. Real-YMFM проверка Main → Options → Main
на 18 000 native-кадрах зарегистрировала 958 изменений высоты и ни одного
повторного запуска, остановки или перезагрузки музыкального драйвера.
