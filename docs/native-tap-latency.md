# Visible-cell input without hidden-camera travel

The browser gesture recognizer queues a short tap synchronously on pointer
release. It has no tap timer or compatibility-click wait. Drag/pinch still
cancel a pending tap and never send contextual A.

The avoidable delay was below that recognizer: the upstream mouse adapter had
to move its hidden 320×224 native camera toward a world-space target at at most
seven pixels per native frame. A target could already be visible in the
expanded browser viewport and still wait several hundred milliseconds for
this invisible journey.

`em_web_world_intent.h` now keeps the ordinary legacy cursor legal using its
existing clamp while supplying the retained requested world tile at the same
native picker checkpoints (`$6486` / `$701C`). It queues the same A edge and
releases the target lock only when original A enters `$27B80`. Original lookup,
selection, movement, attack, Palace activation, pathfinding and their guards
continue through the Sega procedures. The helper takes `const CPU *`: it changes
host mouse intent only, and writes no CPU registers, camera, units or clocks.
Targets outside the original mission rectangle retain legacy reachability.

## Fresh native evidence — 2026-11-05

`tools/test_em_web_tap_latency.c` compares the previous shipping observer with
the current observer against the genuine Harkonnen authored demo CPU. The
ordinary A entry receives exactly the requested native tile in both paths.
Results compare selected unit/building and original action, actor, target,
target kind and source procedure.

| Case | Previous A entry | Current A entry |
| --- | ---: | ---: |
| Nearby building | 3 native frames | 3 |
| Distant visible building | 22 | 3 |
| Distant empty cell | 47 | 3 |
| Selected Devastator: move | 48 | 3 |
| Selected Devastator: attack building | 21 | 3 |
| Armed Palace: exact cell1618 | 6 | 3 |
| Distant visible Devastator | 30 | 3 |

At nominal60Hz,48 frames are800ms and3 frames are50ms. These are native
input-to-A-entry frame counts, **not physical iPhone latency or browser paint
measurements**. The original handler must finish and the browser must present
its result. No fake early selection or simulated order acknowledgment is used.
The current path keeps the hidden native camera at its pre-tap coordinates.

The test checks the entire CPU structure before/after every active host-intent
observation. The nearby-building case reaches original A on the same tick in
both paths; after that handler returns, all391624 CPU/device bytes also match
exactly. It also runs120 native frames with no input and compares both
paths: all391624 CPU/device bytes, all384496 generated PCM bytes,865 serialized
real YMFM bytes, master-cycle count and instruction count are identical.
Explicit cancellation issues no later command. Out-of-mission checks change
neither CPU nor mouse state.

The earlier Palace cursor-drift proof in `native-world-input-qa.md` remains
historical evidence for its recorded headers/builds. Its native regression now
expects legacy camera movement only in its negative control; shipping quiet
and stale-hover cases must keep the exact target and stationary native camera.
Those historical logs are not relabelled as new results.

## Re-run

The test uses the authored CPU+YMFM reference generated by the existing demo
fixture tools under `.local/demo-fixture-harkonnen/`. It does not use a fabricated
selector, enemy, price, HP or order implementation. After preparing the pinned
native sources and the red fixture:

```sh
mkdir -p .local/tap-latency-20261105
clang++ -std=c++17 -O2 -c .local/source/genesis_recompiler/audio_ymfm.cpp -o .local/tap-latency-20261105/ymfm.o
clang -std=c11 -O1 -Itools -I.local/source/genesis_recompiler -c tools/test_em_web_tap_latency.c -o .local/tap-latency-20261105/test.o
clang++ .local/tap-latency-20261105/test.o .local/tap-latency-20261105/ymfm.o -lm -o .local/tap-latency-20261105/test
.local/tap-latency-20261105/test
```

The serialized DSAV v2 structure and payload layout are unchanged. Existing
saves require compatible-core recognition by the web file envelope when the
WASM hash changes; the original native payload itself is not migrated or
rewritten by this input optimization.
